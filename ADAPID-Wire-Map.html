The whole system

Overview: four wire hops, five stores

Hop names are used everywhere on this page. W1 phone to backend upload. W2 ML pulls training sessions from the backend. W3 backend sends one session to ML for a verdict. W4 backend calls the external keystroke AI. R1–R5 are the at-rest formats: phone checkpoint, Oracle, Redis/Celery, ML staging file, ML job spool and bundles.

What every receiver sees after decoding

The exact dict json.loads returns today: same int/float types, same null vs missing vs empty list, same key order. That is why the boxes behind each seam stay grey.

Upload size, median session

367 KB gzip JSON today, 94 KB for columnar protobuf + gzip (measured on 43 sessions). Largest: 1,317 KB to 296 KB.

What does not move

Oracle schema, Celery messages, the keystroke-AI call, every response body, the training CSVs and the bundles.

The 94 KB / 296 KB and the 22.4 ms decode figures were measured with touches, keys and metadata as typed rows. The v2 plan carries those parts as a generic interned object, so they must be re-measured in rollout step 1. Sensors are over 90% of the bytes, so a few per cent of drift is the expectation. W2 and W3 sizes in the v2 format were not measured.

The code comment at SensorDataCollector.kt:273-277 puts a Gson sample at about 1.4 KB of heap. A columnar row is about 40 B, so a 40,000-sample session drops from roughly 56 MB to roughly 2 MB. These are estimates from the code comment, not a device measurement. MAX_SENSOR_SAMPLES stays at 40,000 so the training data does not change shape.

Side 2 · server

Why float32 is lossless here: the SDK widens every sensor value with .toDouble() before Gson writes it (SensorDataCollector.kt:673-720, 730, 770). All 2,679,280 sensor values in the corpus passed the float32 round-trip check. Touch and path coordinates do not pass it, so they travel as doubles produced exactly the way Gson writes them today (Float.toString(), then parsed as a double).

Guarantees

What never changes

Data in Oracle

Same tables, columns, JSON text columns and row values. Gate: one session uploaded as JSON and as v2 gives identical rows.

Training data

sessions.json is byte-identical, so the CSVs, census, DTW templates and bundles are identical. Gate: column-for-column CSV diff.

Predict results

Same dict into extract_session, so the same risk score. Gate: JSON, JSON+zstd, v2 and v2+zstd give identical responses.

Every response body

App, backend, ML and keystroke-AI responses stay JSON. The SDK only learns to read one extra header.

Keystroke path

behaviour_data.keystroke still reaches the backend unchanged and still goes to the keystroke AI as JSON.

Rollback

Every step has a switch: NAV_FETCH_WIRE, ML_PREDICT_WIRE, ADVERTISE_WIRE. The JSON paths are never deleted.
